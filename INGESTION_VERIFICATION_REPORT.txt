2. DEFECT RESOLUTION: NULL CHARACTER IN SUBPROCESS PIPELINE
================================================================================
2.1 Defect Background:
Ingestion of C3085-RPT-3EH6105-AC-0000001(4).pdf previously failed with:
"ValueError: embedded null character" inside a subprocess call. On Windows,
the Win32 CreateProcess API rejects command line strings containing the '\x00'
null byte. The root cause was broken ToUnicode CMap font tables inside Table 2
(page 8) and Table 11 that emitted null and unprintable C0 control bytes during
text decoding.

2.2 Remediations Implemented:
1. extract.py:
   - Implemented _sanitize_pdf_text(raw) to strip '\x00' and C0 control characters
     [\x01-\x08\x0b\x0c\x0e-\x1f] while strictly preserving whitespace (\t, \n, \r).
   - Applied around page.get_text("text") in extract_pdf().

2. services/pipeline.py:
   - Added defense-in-depth text = text.replace('\x00', '') right after page text
     extraction in process_document_pipeline().

3. services/vision_adapter.py:
   - Hardened run_visual_worker() before invoking subprocess.run():
     safe_text = (page_text or '').replace('\x00', '')[:500]
   - Prevents null characters from ever reaching Windows command-line arguments.

4. tests/test_null_character_handling.py:
   - Created test suite with 18 automated unit and integration tests.
   - 18 / 18 tests passing.

2.3 Regression Test Results:
- Full repository regression suite executed:
