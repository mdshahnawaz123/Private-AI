1. EXECUTIVE SUMMARY & OBJECTIVES
================================================================================
This report documents the architectural inspection and implementation plan for 
integrating a dedicated, locally hosted image-generation backend (ComfyUI) into 
the existing Expo Design AI application.

Key Objectives:
- Connect Expo Design AI to a local ComfyUI instance (http://127.0.0.1:8188)
  via HTTP and WebSocket APIs.
- Deliver three initial architectural design workflows:
    * Workflow A: Text-to-Image Architectural Concept Generator.
    * Workflow B: Sketch or Reference Image to Render (Img2Img / Conditioning).
    * Workflow C: Render Enhancement & Photorealistic Refinement.
- Keep ComfyUI as an isolated backend service. The Expo Design AI frontend communicates
  strictly with the Expo Design AI backend, which owns authentication, project
  isolation, parameter validation, queueing, and image storage.
- Design strictly within the 16 GB VRAM hardware boundary of the NVIDIA RTX 5080,
  preventing Out-Of-Memory collisions with active Ollama LLM/VL workloads through
  single-job serialization.
- Fully offline operation: zero external network calls, zero telemetry, zero
  automatic weight downloads.
- Maintain 100% backward compatibility and preserve all 353 baseline tests.

       |-- Router: /api/image-engine/*
       |-- Job Service & FIFO Queue (SQLite WAL)

       |-- Image Storage: data/projects/{id}/generated_images/
       |

  ComfyUI Local Service (127.0.0.1:8188)
       |-- Latent Sampling & UNet Execution
       |-- GPU Execution: NVIDIA RTX 5080 (16 GB VRAM)
       |-- Local Output: ComfyUI/output/
       |
       v  [HTTP GET /view]
  Image Retrieval & Ingestion into Authorized Project Storage

Ownership Boundaries:
- Expo Design AI owns:
    * Authentication, authorization, project membership checks.
    * Input validation, prompt sanitization, resolution clamping.
    * Persistent job tracking, status reporting, and FIFO queueing.
    * Project file storage, thumbnails, and metadata sidecars.
    * User-facing UI, queue status display, and gallery.
- ComfyUI owns:
    * Workflow execution, node graphs, model loading, and tensor computation.
    * VRAM memory management and latent decoding.

================================================================================
4.1 Module Structure:
services/image_engine/
  ├── __init__.py           # Package exports
  ├── schemas.py            # Pydantic v2 data models for API contracts
  ├── comfyui_client.py     # Async HTTP & WebSocket client for ComfyUI

4.2 Database Schema Extensions (db.py):
- ImageJob table:
    * id: String(64) primary key (UUID)
    * project_id: Integer foreign key (projects.id)
    * user_id: Integer foreign key (users.id)
    * workflow_id: String(100)
    * status: String(30) ('queued', 'running', 'completed', 'failed', 'cancelled')
    * comfy_prompt_id: String(100)
    * input_params: JSON
    * progress: Integer (0 - 100)
    * error_message: Text
    * created_at: DateTime
    * completed_at: DateTime
- ImageOutput table:
    * id: String(64) primary key (UUID)
    * job_id: String(64) foreign key (image_jobs.id)
    * filename: String(255)
    * file_path: Text
    * width: Integer
    * height: Integer
    * seed: Integer
    * output_metadata: JSON
    * created_at: DateTime

4.3 Starter Workflows Specification (workflows/):
- Workflow A (architecture_concept.json):
    * Type: Text-to-Image concept generator.
    * Inputs: design brief, architectural style, building type, width, height, seed, steps.
    * Node graph: UNetLoader/CheckpointLoader -> CLIPTextEncode -> KSampler -> VAEDecode -> SaveImage.
- Workflow B (sketch_to_render.json):
    * Type: Image-to-Image / Sketch-to-Render.
    * Inputs: prompt, input sketch/massing image, denoise strength (0.3 - 0.8), seed.
    * Node graph: LoadImage -> VAEEncode -> KSampler -> VAEDecode -> SaveImage.
- Workflow C (render_enhancement.json):
    * Type: Render enhancement & photorealistic refinement.
    * Inputs: base 3D render, prompt, refine strength, upscale factor, seed.
    * Node graph: LoadImage -> Upscale/Refine -> KSampler -> VAEDecode -> SaveImage.

5. BACKEND API SPECIFICATION (/api/image-engine/*)
================================================================================
1. GET /api/image-engine/status
   - Description: Health check of ComfyUI connection, GPU stats, active queue count.
   - Response: {"available": bool, "base_url": str, "queue_depth": int, "device": str}
   - Access: Authenticated user.

2. GET /api/image-engine/workflows
   - Description: List registered workflows and their configurable parameters.
   - Response: {"workflows": [{"id": str, "name": str, "version": str, "available": bool, "parameters": [...]}]}
   - Access: Authenticated user.

3. POST /api/image-engine/jobs
   - Description: Submit a generation job. Supports multipart/form-data for image uploads.
   - Request: {project: str, workflow_id: str, prompt: str, style: str, width: int, height: int, ...}
   - Response: {"job_id": str, "status": "queued", "position_in_queue": int}
   - Access: Project member / Lead / Admin (guarded by auth.require_project).

4. GET /api/image-engine/jobs/{job_id}
   - Description: Poll job status, progress percentage, execution duration, and errors.
   - Response: {"job_id": str, "status": str, "progress": int, "error": str, ...}
   - Access: Project member.

5. GET /api/image-engine/jobs/{job_id}/outputs
   - Description: Get metadata and URLs for generated output images.
   - Response: {"outputs": [{"id": str, "filename": str, "url": str, "thumbnail_url": str, "seed": int}]}
   - Access: Project member.

6. GET /api/image-engine/outputs/{output_id}/file
   - Description: Stream authenticated image binary with project access validation.
   - Access: Project member.

7. POST /api/image-engine/jobs/{job_id}/cancel
   - Description: Request cancellation of a queued or running job.
   - Response: {"success": bool, "job_id": str, "status": "cancelled"}
   - Access: Job owner or Admin.

6. HARDWARE & RESOURCE MANAGEMENT PLAN (RTX 5080 16 GB VRAM)
================================================================================
Hardware Constraints:
- NVIDIA RTX 5080: 16 GB VRAM.
- Co-located with Ollama LLM / Vision models (qwen3.5:9b / qwen2.5vl:7b) and Windows DWM.
- Available unallocated VRAM during inference: ~10 to 12 GB.

Resource Protections:
1. Strict Single-Worker Serialization:
   - image_engine_concurrency = 1.
   - Only ONE diffusion job runs at a time. All other requests wait in the SQLite FIFO queue.
2. Safe Resolution Limits:
   - Validated dimensions: 512x512 up to 1024x1024 (multiples of 64 only). Arbitrary resolutions rejected.
3. Quantized Model Recommendations:
   - Support memory-efficient checkpoints: FLUX.1 [dev] FP8, GGUF Q4/Q8, or SDXL turbo.
4. CUDA OOM Handling:
   - WebSocket listener intercepts execution errors from ComfyUI.
   - If "OutOfMemoryError" occurs, job status transitions to "failed" with user-friendly advice:
     "GPU out of memory. Please reduce output resolution or wait for other tasks to complete."
   - Never crashes the FastAPI backend or forces uncontrolled process restarts.

8. SECURITY, OFFLINE OPERATIONS & PATH TRAVERSAL CONTROLS
================================================================================
1. Cross-Project Isolation:
   - Every ImageJob is bound to a validated project_id.
   - Output images and uploads are stored under:
     data/projects/{project}/generated_images/{job_id}/
   - File serving endpoints verify user membership via auth.require_project().
2. Path Traversal Prevention:
   - All input filenames and destination paths are passed through
     services.ingestion.contained_upload_path(). Path traversal attempts are rejected.
3. Offline Enforcement:
   - ComfyUI client binds strictly to localhost (127.0.0.1).
   - Zero telemetry, zero external model downloading.
   - The application functions normally even when ComfyUI is unavailable.
