## 4. Audit Observations & Adjustments Made

1. **Baseline Test Count Discrepancy:**
   * The audit mentioned "267 passing tests". The actual baseline count in this codebase using Python 3.12 is **320 tests**. All 320 were verified passing before any modifications.
2. **`StructuredRecord` Schema & AST Invariant:**
   * The audit recommended setting `existing.status = status`. Inspection revealed `StructuredRecord` in `db.py` **has no `status` column**; status information is mapped to `confidence` (`HIGH` or `AMBIGUOUS`).
   * Furthermore, `tests/test_release_recovery.py` contains an AST-based invariant test asserting that `process_document_pipeline` does not make `.status` assignments (as document status is managed by the higher-level caller).
   * Accordingly, `services/pipeline.py` updates `existing.value`, `existing.raw_value`, `existing.confidence`, `existing.schedule`, `existing.row_label`, and `existing.column_label`.
3. **Table Identity at Location 2:**
   * The audit referred to "StructuredRecord and the other table at the second location". In reality, both locations in `services/pipeline.py` operate on `db.StructuredRecord` (Location 1 for `PDF_NATIVE` and Location 2 for `PDF_IMAGE`). `db.ScheduleRow` is populated in `knowledge/extraction.py:index_structured_tables()`, which already purges old rows for `(project_id, filename)` prior to re-indexing.

## 5. Side Effects & Re-Indexing Instructions

### Side Effects
* **Stale Records Purged on Next Upload:** Re-uploading a document revision will now cleanly delete obsolete `StructuredRecord` rows that no longer exist in the new revision.
* **Slight Increase in FAISS Chunks for Multi-Table Documents:** Documents with multi-level tables will have an extra chunk per table page (`[STRUCTURED TABLE]`), allowing cross-encoder and BM25 retrievers to surface full column hierarchy.
* **DocumentMemory Generation for All Uploads:** Newly uploaded documents will now run the `build_memory_for_document` pass during ingestion when `enable_document_memory=True`.

### Re-Indexing Existing Documents
Documents uploaded **before** Fix 2 was applied were vectorized without `[STRUCTURED TABLE]` chunks. To update existing documents:

1. **Via Admin Web UI:**
   Navigate to the Documents tab and click **Re-index** (or **Re-process**) on the target document.
2. **Via Headless Python Script:**
   ```python
   import json
   from main import index_structured, DOCS_DIR
   import os

   project = "YourProjectName"
   filename = "YourDocument.pdf"
   doc_path = os.path.join(DOCS_DIR, project, filename)
   meta_path = doc_path + ".index.json"

   if os.path.exists(meta_path):
       with open(meta_path, "r", encoding="utf-8") as f:
           meta = json.load(f)
       chunks_indexed = index_structured(project, meta, filename)
       print(f"Re-indexed {chunks_indexed} chunks with header-inherited tables for {filename}.")
   ```
