### 4. Audit Discrepancies and Observations

1. **`EntityExtractor` Class**:
   - *Audit Statement*: "call EntityExtractor during document ingestion so those tables get populated."
   - *Reality*: The repository had no `EntityExtractor` class; it had `index_structured_entities(...)` inside `knowledge/extraction.py`.
   - *Resolution*: Created `class EntityExtractor` with `extract_and_index()` and `extract()` methods wrapping `index_structured_entities`, ensuring compatibility with both functional and object-oriented caller patterns.
2. **Entity ID Collisions**:
   - The legacy `index_structured_entities` used non-unique IDs like `auto-0`, which would collide and overwrite across different documents under SQLite's unique constraint `(project_id, req_id)`.
   - Updated ID generation to prefix the sanitized filename: `f"{clean_fn}-req-{counts['requirements']}"` and `f"ev-{clean_fn}-p{pg_num}-{counts['evidence']}"`.
3. **GraphEdge and Provenance Field Shapes**:
   - `ProvenanceTracker.create()` returns a Python `dict`, not an object with attributes.
   - `GraphEdge` has a `properties` attribute, not `metadata`.
   - `knowledge/hub.py` was updated to defensively inspect both dict keys and object attributes.
4. **Hub Instance Isolation**:
   - Setting `load_db=False` by default in `KnowledgeHub.__init__` allows unit tests (like `test_project_cleanup.py`) to construct isolated in-memory test fixtures without SQLite state leakage, while the global production singleton `_hub = KnowledgeHub(load_db=True)` loads from SQLite on server boot.
