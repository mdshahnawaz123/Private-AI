## Failure diagnosis

1. **F&B count — STRUCTURED_EXTRACTION.** Re-running the existing `table_row_units` function on the stored geometry tables produces both `ITEM: F&B Units:; NO.: 5` and `ITEM: TOTAL; NO.: 10` under the inherited title `Table: F&B Units:`. The combined total acquires misleading scope before retrieval and reasoning. LLM reasoning then invents implied extra entries, and answer validation fails to reject the relationship error. Correct the table relationship first, invalidate affected derived generations, and test the raw table through the final answer.
2. **GFA comparison — QUERY_PARSER.** Current exact-answer source chooses `proposed` before `allowed` when both appear. The live 0.03-second response matches that single-value route. Resolve comparison intent and both operands before permitting a final answer. Exact live function/prompt tracing was not collected; code inspection and output establish the supported diagnosis, not an instrumented full trace.
3. **Generic floor area — SEMANTIC_RESOLUTION.** Server logs show a memory answer for this request. It selects one valid area type without disclosing the others. Candidate coverage/ranking and ambiguity handling need a targeted trace before distinguishing which memory substep first lost alternatives.
