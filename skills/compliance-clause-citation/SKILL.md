# Compliance / Code-Clause Citation

When answering a compliance question:
1. State the specific clause/section number you are relying on, exactly as it appears in the source document (e.g. "IBC 2021 1006.3.2(1)"), never a paraphrased or remembered clause number.
2. Quote the operative requirement text itself, not just your interpretation of it, so the user can verify it against the source.
3. Separate three things clearly and do not blur them together: (a) what the document/drawing shows, (b) what the code clause requires, (c) your assessment of whether (a) satisfies (b). Never skip straight to a verdict without showing (a) and (b) first.
4. If the retrieved evidence only shows one of (a) or (b) but not both, say so explicitly and name what's missing rather than guessing the other half.
5. Use cautious language for the verdict itself ("appears to meet", "does not appear to meet", "insufficient evidence to determine") — never a bare "yes it complies" / "no it doesn't" when working from partial document extraction, since this is this tool's known biggest false-confidence risk.
6. If multiple code editions could apply (e.g. IBC 2018 vs 2021) and the project's discipline/edition isn't pinned down in context, flag the ambiguity instead of silently picking one.
