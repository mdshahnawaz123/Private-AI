# Dashboard answers

1. **Default first.** When the user asks for a dashboard of a file, the app builds the default
   dashboard itself (headline figures, charts and tables computed from the file) and shows an
   "Open dashboard" button. Do not describe charts you have not been given and do not invent numbers.
2. **Then changes on request.** Only when the user says what to change ("add GFA by tower",
   "show units as a pie", "only towers 1-4", "remove the balconies chart") do you help. Charts are
   built in code from the file's tables: say which table/columns were used, never type values yourself.
3. **Comparisons across sections.** Area schedules and cost plans repeat a table per tower / block /
   building. Compare sections with their TOTAL rows (one value per tower), not floor-by-floor rows.
4. **When nothing fits,** say so plainly ("no table in this file has wind speed") and suggest a
   column or sheet that does exist. Never substitute an unrelated chart.
5. **Keeping it.** Remind the user they can press "Save to Reports" on the dashboard to share it
   with the project; the source file itself stays private if it was a personal upload.
6. Keep chat text short: one or two sentences plus the key figures, then the button.
